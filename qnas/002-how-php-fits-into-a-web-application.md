# 002 - How PHP Fits into a Web Application: Questions and Answers

Use this Q&A to review [002 - How PHP Fits into a Web Application](../lessons/002-how-php-fits-into-a-web-application.md). Answers and explanations appear directly after each question.

## Multiple-choice questions

### 1. What is the browser's role in a typical PHP web application?

A. It executes the server's PHP source code<br>
B. It sends requests and displays the responses it receives<br>
C. It stores every application's database<br>
D. It replaces the web server

**Answer: B.** The browser acts as the visitor's client. It requests resources, receives responses, and displays documents such as HTML pages.

### 2. Which part receives HTTP requests and sends HTTP responses?

A. The web server<br>
B. The CSS stylesheet<br>
C. The HTML document<br>
D. The database table

**Answer: A.** The web server handles HTTP connections and determines how requests are served. It may return static files or route requests to PHP application code.

### 3. What does the PHP runtime do in this flow?

A. It paints pixels on the visitor's screen<br>
B. It executes PHP source code<br>
C. It defines the page's CSS rules<br>
D. It replaces the HTTP request

**Answer: B.** The runtime executes PHP code. The web server uses the result when it forms a response for the browser.

### 4. Which three parts are commonly found in an HTTP response?

A. Status, headers, and body<br>
B. Browser, keyboard, and screen<br>
C. PHP, CSS, and database<br>
D. URL, folder, and file extension

**Answer: A.** The status describes the result, headers provide response metadata, and the body contains the returned content such as HTML or JSON.

### 5. Which is an example of a dynamic response?

A. A fixed image file returned as-is<br>
B. A PHP page that changes its greeting based on application data<br>
C. A stylesheet file stored on disk<br>
D. A logo file that never changes

**Answer: B.** Application logic can use a route, input, or stored data to produce different content. The other examples can be served as static resources.

### 6. What is true about a database in a PHP application?

A. Every PHP request must use one<br>
B. PHP cannot run without one<br>
C. An application may use one, but it is optional<br>
D. A database is the same thing as a PHP runtime

**Answer: C.** Many applications store information in a database, but a simple PHP page or command-line program can work without one.

### 7. What does a query string usually contain?

A. Values included in a URL after a question mark<br>
B. The PHP source code<br>
C. The CSS rules for a page<br>
D. The response body only

**Answer: A.** In a URL such as /greeting?name=Asha, the part after the question mark is the query string. PHP can expose query-string values to a script.

### 8. Which statement about routes is correct?

A. Every route must be the name of a physical file<br>
B. An application can map a URL path to code without a matching file<br>
C. Routes only exist in CSS<br>
D. The browser creates all server routes

**Answer: B.** A web server or application can direct a URL path to application logic. The path does not have to correspond to a file on disk.

### 9. Which technology usually describes page structure and meaning?

A. PHP runtime<br>
B. HTML<br>
C. Database<br>
D. HTTP status

**Answer: B.** HTML describes document structure. PHP may generate the HTML, while CSS styles it and JavaScript can add browser-side behavior.

### 10. How should an application treat values supplied in a request?

A. As trusted because the web server received them<br>
B. As trusted if they are in a URL<br>
C. As untrusted input that must be handled carefully<br>
D. As PHP source code

**Answer: C.** Request data comes from outside the application. Validate it for the task and escape it for the context where it will be displayed.

## True or false

### 1. PHP normally executes before its response reaches the browser.

**Answer: True.** In a typical PHP website, the server runs PHP and sends the generated response to the browser.

### 2. The web server and the PHP application have exactly the same role.

**Answer: False.** The web server handles HTTP requests and responses. The PHP application contains logic that decides what the request means and what content to produce.

### 3. A PHP application can return JSON instead of HTML.

**Answer: True.** PHP can produce different response bodies. JSON is commonly used when a browser script or another client needs data rather than a full HTML page.

### 4. A URL path always points to a file with the same name on disk.

**Answer: False.** Applications can map routes to code. A route can exist even when there is no matching physical file.

### 5. Every resource requested from a site must be generated by PHP.

**Answer: False.** A web server can serve static resources such as images and stylesheets directly, while routing dynamic page requests to PHP.

### 6. A database is required for a PHP page to display a fixed greeting.

**Answer: False.** PHP can generate a response from fixed content without contacting a database.

## Short-answer questions

### 1. Describe the basic request-response journey for a PHP page.

**Answer:** A browser sends a request to a web server. The server may pass it to the PHP application. PHP runs the needed logic and produces a response, which the server sends back to the browser for display.

### 2. Name four details that can be part of an HTTP request.

**Answer:** A request can include a method, a path, headers, and optionally a body or query string.

**Explanation:** Which details are present depends on the kind of request. For example, a URL can include a query string, while a request may also carry a body.

### 3. What is the difference between a static and a dynamic response?

**Answer:** A static response can be returned as a resource without running application logic for each value. A dynamic response is produced by executing logic and may depend on a route, input, or saved data.

### 4. What information is in an HTTP response?

**Answer:** A response has a status, headers, and a body. The body may contain HTML, JSON, plain text, or other content.

### 5. Why might a PHP application communicate with a database?

**Answer:** It may need to read or save information, such as account details or product records. A database is optional and is only used when the application needs persistent data.

### 6. What is one way PHP and JavaScript can work together?

**Answer:** PHP can generate an HTML page or JSON response on the server. JavaScript in the browser can use that response to update or add behavior to the page.

### 7. Why should query-string values not be printed directly into HTML?

**Answer:** A visitor can control request values. The application should validate values for their intended use and escape them for HTML before displaying them.

## Trace the flow

### 1. A visitor requests /greeting?name=Asha. What does each part do?

**Answer:** The browser sends the request. The web server routes it to the PHP application. PHP can read the request data, prepare a response, and return it through the web server. The browser then displays the response.

**Explanation:** The query string contains the value name=Asha, but it is still input from outside the application. It must be handled safely before use.

### 2. The requested resource is a logo.png image. Does PHP have to generate it?

**Answer:** No. The web server can return the image file directly as a static resource.

**Explanation:** PHP is useful for dynamic behavior, but not every request needs to run application code.

### 3. A page displays a list of products saved in a database. Which parts might participate?

**Answer:** The browser requests the page, the web server routes the request to PHP, the application asks the database for product data, PHP creates a response, and the browser displays the result.

**Explanation:** The database supplies stored information, PHP applies application logic and forms output, and the browser renders the response. A simple application may use fewer parts.
