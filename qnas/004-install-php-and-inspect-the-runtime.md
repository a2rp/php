# 004 - Install PHP and Inspect the Runtime: Questions and Answers

Use this Q&A to review [004 - Install PHP and Inspect the Runtime](../lessons/004-install-php-and-inspect-the-runtime.md). Each answer follows its question and includes an explanation where useful.

## Multiple-choice questions

### 1. What must be installed to execute PHP programs?

A. A PHP runtime<br>
B. A text editor only<br>
C. A browser extension only<br>
D. A database only

**Answer: A.** The PHP runtime parses and executes PHP code. An editor can help write the code but does not execute it by itself.

### 2. What does PATH help the terminal do?

A. Find the folder containing the PHP executable<br>
B. Change the PHP language version<br>
C. Enable every PHP extension<br>
D. Create a database

**Answer: A.** PATH is a list of directories the shell searches for commands. Add the directory containing php.exe or php to PATH, not the executable file path itself.

### 3. Which command prints the PHP version available to a terminal?

A. php -v<br>
B. php --ini<br>
C. php -m<br>
D. php --ri json

**Answer: A.** The -v option prints the version and runtime information for the PHP executable the terminal resolves.

### 4. What does php --ini show?

A. A list of all website pages<br>
B. PHP configuration file search and load information<br>
C. Every application database<br>
D. The HTML generated by PHP

**Answer: B.** The command reports where PHP looks for configuration, which php.ini it loaded, and additional scanned configuration files.

### 5. Which command lists extensions loaded by the CLI runtime?

A. php --version<br>
B. php --ini<br>
C. php -m<br>
D. php --server

**Answer: C.** The -m option lists loaded PHP and Zend modules for the runtime invoked by the terminal.

### 6. On Windows, what should be added to PATH?

A. The php.exe file itself<br>
B. The folder that contains php.exe<br>
C. The php.ini file<br>
D. The folder containing the project README

**Answer: B.** PATH contains directories. Once the PHP folder is on PATH and the terminal is reopened, the shell can find php.exe by its command name.

### 7. If php --ini reports that no configuration file is loaded, what does that always mean?

A. PHP is corrupt<br>
B. PHP cannot run at all<br>
C. Nothing by itself; PHP may run with built-in defaults<br>
D. The web server is configured correctly

**Answer: C.** Some installations can run without a loaded php.ini. Whether a configuration file is needed depends on the installation and the application's requirements.

### 8. What might php --ri json show?

A. Configuration information for the JSON extension<br>
B. All PHP source files on disk<br>
C. The current user's browser history<br>
D. The version of Windows

**Answer: A.** The --ri option displays information for a PHP extension. The lesson uses JSON as an example.

### 9. Why can a PHP command work in PowerShell while a website uses a different version?

A. The CLI and web server can use separate PHP runtimes<br>
B. PowerShell changes every server version<br>
C. Websites cannot use PHP versions<br>
D. PHP ignores server configuration

**Answer: A.** The command-line installation and web-server configuration may point to different executables, settings, or extensions.

### 10. Why should you verify a version installed by a package manager?

A. Package names always install the newest branch<br>
B. Available package versions vary by operating system and source<br>
C. PHP has no version numbers<br>
D. Package managers only install editors

**Answer: B.** A distribution may package an older branch. Check the installed version against the project's requirements and the current support schedule.

## True or false

### 1. Installing an editor installs PHP automatically.

**Answer: False.** An editor is used to write and manage files. PHP must be installed separately as a runtime.

### 2. After changing PATH, a terminal that was already open may need to be restarted.

**Answer: True.** A shell reads its environment when it starts. Open a new terminal so it sees the updated PATH.

### 3. php -m shows the extensions loaded by every PHP runtime on the computer.

**Answer: False.** It shows modules for the one PHP executable invoked in that terminal. A web server or another PHP installation may load a different set.

### 4. On Windows, copying php.ini-development to php.ini can provide a starting configuration for local development when the distribution includes those files.

**Answer: True.** The development template can be used as a starting point. Development error-display settings should not be copied unchanged to a public production server.

### 5. php -v verifies the version used by a website.

**Answer: False.** It verifies the PHP executable found by the terminal. The web server's runtime must be checked separately.

## Short-answer questions

### 1. What is the difference between PHP and a code editor?

**Answer:** PHP is the runtime that executes PHP programs. A code editor is an application for creating and editing source files.

### 2. What does Get-Command -All php help you find in PowerShell?

**Answer:** It shows the PHP commands PowerShell can resolve and where they are located. This can help identify multiple installations or an unexpected PATH order.

### 3. What does command -v php do on macOS or Linux?

**Answer:** It prints the path of the PHP command that the current shell resolves.

### 4. Why should you use php --ini before editing PHP settings?

**Answer:** It identifies the configuration file actually used by that CLI runtime. Editing a different php.ini may have no effect on the command being inspected.

### 5. What does php -m tell you, and what does it not tell you?

**Answer:** It lists extensions loaded by the CLI runtime. It does not guarantee that another PHP runtime, such as a web-server runtime, loads the same extensions.

### 6. Why might you choose a package manager for macOS or Linux?

**Answer:** It provides a platform-specific way to install and maintain PHP packages. The installed version still needs to be checked because package availability differs by distribution.

### 7. What should you do if PHP is installed but the terminal says it cannot find php?

**Answer:** Find the folder containing the PHP executable, add that folder to PATH, open a new terminal, and check the resolved command again.

## Troubleshooting practice

### 1. PowerShell says php is not recognized, but C:\tools\php\php.exe -v prints a version. What is the likely problem?

**Answer:** PHP is installed, but the directory containing php.exe is probably missing from PATH, or the open terminal has not refreshed its environment.

**Explanation:** Add the PHP directory to PATH, start a new PowerShell session, and try Get-Command -All php again.

### 2. php -v reports the expected version, but an application says an extension is missing. What should you check?

**Answer:** Run php -m for the CLI runtime and compare the result with the application's requirements. If the application runs through a web server, inspect that server's PHP runtime separately.

**Explanation:** The extension may be absent or disabled, or the website may use a different PHP installation and configuration.

### 3. You edit php.ini but a command's behavior does not change. What is your next step?

**Answer:** Run php --ini using the same PHP command and check the loaded configuration path. Confirm that the edited file is the file used by that runtime.

### 4. A teammate's website uses a different PHP version from their terminal. Is that necessarily an installation error?

**Answer:** No. CLI PHP and web-server PHP can be separate installations configured independently. The important step is to identify and verify each runtime used by the project.

### 5. A package manager installs a PHP version below the project's minimum. What should you do?

**Answer:** Choose an installation source or package version that satisfies the project requirement, then verify the installed result with php -v. Do not assume the package label means the version is suitable.
