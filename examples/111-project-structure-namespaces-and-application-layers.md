# 111 - Project structure, namespaces, and application layers: Example

## Goal

Build a small command-line order registration app with Composer PSR-4 autoloading and clear domain, application, infrastructure, and presentation responsibilities.

## Question

How can a PHP project keep an order rule independent from the command-line interface and storage implementation, while still connecting those pieces into a usable application?

## Assumptions

- PHP 8.1 or newer and Composer are available.
- Commands are run from the project root.
- This is a small command-line demonstration, so it uses `bin/` and does not need a web `public/` directory.
- The in-memory repository stores orders only while this process runs. Replace it with persistent storage for a real application.
- The PHP code is provided for study; it was not executed here.

## 1. Create the project structure

~~~text
order-demo/
├── bin/
│   └── demo.php
├── src/
│   ├── Application/
│   │   └── Order/
│   │       ├── OrderRepository.php
│   │       └── RegisterOrder.php
│   ├── Domain/
│   │   └── Order/
│   │       ├── Order.php
│   │       └── OrderItem.php
│   └── Infrastructure/
│       └── Persistence/
│           └── InMemoryOrderRepository.php
├── .gitignore
└── composer.json
~~~

Each location has a focused role:

- `bin/demo.php` is the command-line entry point and composition root.
- `src/Domain/Order/` contains order concepts and their rules.
- `src/Application/Order/` contains the use case and the persistence contract it needs.
- `src/Infrastructure/Persistence/` contains one concrete repository implementation.
- `vendor/` will be generated by Composer and ignored by Git.

## 2. Configure Composer autoloading

Create `composer.json`:

~~~json
{
    "name": "example/order-demo",
    "type": "project",
    "description": "A small PHP example of project structure and application layers",
    "require": {
        "php": "^8.1"
    },
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}
~~~

The `App\\` namespace prefix maps to `src/`. For example, `App\Domain\Order\OrderItem` maps to `src/Domain/Order/OrderItem.php`.

Create `.gitignore`:

~~~gitignore
/vendor/
~~~

From the project root, generate the Composer autoloader:

~~~sh
composer install
~~~

There are no third-party packages in this demonstration. Composer still generates `vendor/autoload.php`, which the entry point loads.

## 3. Define the order item in the domain layer

Create `src/Domain/Order/OrderItem.php`:

~~~php
<?php

declare(strict_types=1);

namespace App\Domain\Order;

use InvalidArgumentException;

final class OrderItem
{
    public function __construct(
        private readonly string $description,
        private readonly int $quantity,
        private readonly int $unitPriceInCents,
    ) {
        if (trim($description) === '') {
            throw new InvalidArgumentException('An item description is required.');
        }

        if ($quantity < 1) {
            throw new InvalidArgumentException('Quantity must be at least one.');
        }

        if ($unitPriceInCents < 0) {
            throw new InvalidArgumentException('Unit price cannot be negative.');
        }
    }

    public function description(): string
    {
        return $this->description;
    }

    public function quantity(): int
    {
        return $this->quantity;
    }

    public function lineTotalInCents(): int
    {
        return $this->quantity * $this->unitPriceInCents;
    }
}
~~~

The item checks rules that should hold regardless of whether an order comes from a web page, a command, or another part of the application. Prices use integer cents to avoid using floating-point numbers for this simple money calculation.

## 4. Define the order in the domain layer

Create `src/Domain/Order/Order.php`:

~~~php
<?php

declare(strict_types=1);

namespace App\Domain\Order;

use InvalidArgumentException;

final class Order
{
    /** @param list<OrderItem> $items */
    public function __construct(
        private readonly string $number,
        private readonly array $items,
    ) {
        if (trim($number) === '') {
            throw new InvalidArgumentException('An order number is required.');
        }

        if ($items === []) {
            throw new InvalidArgumentException('An order must contain at least one item.');
        }

        foreach ($items as $item) {
            if (!$item instanceof OrderItem) {
                throw new InvalidArgumentException('Every order item must be an OrderItem.');
            }
        }
    }

    public function number(): string
    {
        return $this->number;
    }

    /** @return list<OrderItem> */
    public function items(): array
    {
        return $this->items;
    }

    public function totalInCents(): int
    {
        $total = 0;

        foreach ($this->items as $item) {
            $total += $item->lineTotalInCents();
        }

        return $total;
    }
}
~~~

The domain object owns the rule that an order needs a number and at least one valid item. It does not know about HTTP, command-line output, SQL, or Composer.

## 5. Define the application persistence contract

Create `src/Application/Order/OrderRepository.php`:

~~~php
<?php

declare(strict_types=1);

namespace App\Application\Order;

use App\Domain\Order\Order;

interface OrderRepository
{
    public function findByNumber(string $number): ?Order;

    public function save(Order $order): void;
}
~~~

The use case needs to find and save orders. This contract describes those operations without specifying whether the data lives in memory, a relational database, or another store.

## 6. Implement the use case

Create `src/Application/Order/RegisterOrder.php`:

~~~php
<?php

declare(strict_types=1);

namespace App\Application\Order;

use App\Domain\Order\Order;
use App\Domain\Order\OrderItem;
use DomainException;

final class RegisterOrder
{
    public function __construct(
        private readonly OrderRepository $orders,
    ) {
    }

    /** @param list<OrderItem> $items */
    public function execute(string $number, array $items): Order
    {
        if ($this->orders->findByNumber($number) !== null) {
            throw new DomainException('An order with this number already exists.');
        }

        $order = new Order($number, $items);
        $this->orders->save($order);

        return $order;
    }
}
~~~

The application service coordinates one action: reject a duplicate number, create a valid domain order, save it through the contract, and return the result. It does not create a database connection or print terminal output.

## 7. Add an in-memory infrastructure adapter

Create `src/Infrastructure/Persistence/InMemoryOrderRepository.php`:

~~~php
<?php

declare(strict_types=1);

namespace App\Infrastructure\Persistence;

use App\Application\Order\OrderRepository;
use App\Domain\Order\Order;

final class InMemoryOrderRepository implements OrderRepository
{
    /** @var array<string, Order> */
    private array $orders = [];

    public function findByNumber(string $number): ?Order
    {
        return $this->orders[$number] ?? null;
    }

    public function save(Order $order): void
    {
        $this->orders[$order->number()] = $order;
    }
}
~~~

This adapter satisfies the same contract that a database-backed implementation could satisfy. Its data disappears when the command exits, so it demonstrates the boundary but is not persistent storage.

## 8. Connect the application at the entry point

Create `bin/demo.php`:

~~~php
<?php

declare(strict_types=1);

use App\Application\Order\RegisterOrder;
use App\Domain\Order\OrderItem;
use App\Infrastructure\Persistence\InMemoryOrderRepository;

require dirname(__DIR__) . '/vendor/autoload.php';

$repository = new InMemoryOrderRepository();
$registerOrder = new RegisterOrder($repository);

$order = $registerOrder->execute('order-1001', [
    new OrderItem('Notebook', 2, 1250),
    new OrderItem('Pen', 1, 500),
]);

$total = $order->totalInCents();
printf("Order %s saved.\n", $order->number());
printf("Total: $%d.%02d\n", intdiv($total, 100), $total % 100);
~~~

The entry point is the composition root: it chooses the in-memory adapter, constructs the use case, supplies example input, and formats the result for a person using the terminal. `dirname(__DIR__)` makes the autoloader path relative to the script file rather than the caller's current working directory.

Run the example from the project root:

~~~sh
php bin/demo.php
~~~

## Expected output

~~~text
Order order-1001 saved.
Total: $30.00
~~~

The total is two notebooks at $12.50 each plus one pen at $5.00. The example displays the result; it does not start a web server or generate an HTML page.

## How the responsibilities fit together

~~~text
bin/demo.php
    -> RegisterOrder
    -> OrderRepository contract
    -> InMemoryOrderRepository

RegisterOrder
    -> Order and OrderItem domain rules
~~~

The entry point selects the concrete adapter. The use case depends on the application contract and domain types. The domain objects do not depend on the entry point or persistence adapter.

## Replace the adapter without moving the domain rule

A persistent implementation could use PDO while continuing to implement `OrderRepository`. The bootstrap would construct that implementation and pass it into `RegisterOrder`. The use case and domain classes would not need to know the details of SQL connection setup.

For this small sample, adding a PDO adapter would require a database schema and connection configuration, so it is intentionally left out. The repository boundary demonstrates where those details belong without pretending the in-memory store is durable.

## Important notes

- A command-line app uses `bin/`; a web application commonly uses a narrow `public/` document root instead.
- This layout is an example, not a required PHP project template.
- The repository interface is useful here to show how the use case can remain independent of its storage adapter. A real project should keep an abstraction only if that boundary helps.
- `OrderItem` and `Order` validate their own invariants; request-specific validation and error presentation belong at an appropriate application boundary.
- `vendor/` is generated by Composer and should normally be ignored by Git.
- The PHP snippets are provided for study and were not executed here.
