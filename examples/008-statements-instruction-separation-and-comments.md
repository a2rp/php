# 008 - Statements, Instruction Separation, and Comments: Complete Example

This example creates a small PHP-only script and a mixed HTML/PHP page. It uses simple assignments and output statements to show semicolon placement, then adds comments to explain the source without changing its output.

## Question

How do semicolons separate PHP statements, and how can PHP comments document code without becoming part of its output?

## Goal

Create this project:

~~~text
statement-practice/
├── README.md
├── statements.php
└── public/
    └── index.php
~~~

- **statements.php** is a PHP-only CLI script.
- **public/index.php** is a mixed HTML and PHP page.
- **README.md** records the commands to check and run the project.

## Complete code: statements.php

Save this file at the project root:

~~~php
<?php

// Store a name for the first output line.
$name = "Learner";

echo "Hello, ", $name, "!", PHP_EOL;

/*
This block comment spans multiple lines.
It does not become part of the program output.
*/

$topic = "PHP statements"; // The semicolon ends the assignment.
echo "Today you are practicing ", $topic, ".", PHP_EOL;
~~~

This PHP-only file omits a final **?>** tag. Each assignment and **echo** statement has its own semicolon. Both comments are part of the source for readers; neither comment appears in the terminal output.

## Complete code: public/index.php

Create a folder named **public** and save this file inside it:

~~~php
<?php
$pageTitle = "Statements and comments";
$pageMessage = "Each simple PHP statement ends with a semicolon.";
?>
<!doctype html>
<html lang="en">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title><?= $pageTitle ?></title>
</head>
<body>
    <main>
        <h1><?= $pageTitle ?></h1>
        <p><?php echo $pageMessage; ?></p>
        <!-- This is an HTML comment in the page markup. -->
    </main>
</body>
</html>
~~~

The two assignments end with semicolons. PHP then closes its block so the HTML document can continue. The short echo tags output the title, and the later **echo** statement outputs the page message. The HTML comment is markup; it is different from a PHP comment.

## Understand the semicolon rule

Each simple assignment and output statement in the PHP blocks ends with **;**:

~~~php
<?php
$first = "One";
$second = "Two";
echo $first, " and ", $second;
~~~

The semicolon after **$first = "One"** is necessary to separate it from the next statement. A line break alone would not separate the assignment from **$second**.

When PHP reaches **?>**, that closing tag can terminate the final statement before it. For example, the following is allowed:

~~~php
<?php echo "The closing tag ends this final statement" ?>
~~~

Still, include the semicolon before **?>** in normal code because it makes the boundary explicit:

~~~php
<?php echo "The statement ends clearly"; ?>
~~~

The closing-tag rule does not remove the semicolons between earlier statements. In **statements.php**, the final PHP-only file omits **?>**, so its statements end with semicolons as usual.

## Understand the comments

- The **//** comment explains the value assigned to **$name**.
- The **/* ... */** block spans multiple lines and is ignored as PHP source.
- The inline **//** comment explains the semicolon on the same line.
- The **<!-- ... -->** comment belongs to the HTML document, not the PHP source.

Do not use an HTML comment to disable PHP code. The server processes PHP before returning the HTML response. Also avoid nesting **/* ... */** blocks; the first closing marker ends the comment.

## Common mistakes

- **Removing a semicolon between assignments:** PHP reports a syntax error because a newline does not separate the statements.
- **Removing every semicolon before `?>`:** The tag only terminates the final statement in that PHP block. Keep semicolons between earlier statements, and keep the final semicolon for clarity.
- **Using `//` to comment out HTML after `?>`:** The closing tag exits PHP mode, so the following HTML is not part of the PHP line comment.
- **Nesting block comments:** The first ***/** closes the block and can expose later text to PHP parsing.
- **Putting PHP code inside an HTML comment to disable it:** The PHP still executes on the server.
- **Expecting comments to print:** Comments are for source readers; they are not statements that produce output.

## Try changing it

1. Change **$name** and run **php statements.php** again.
2. Add a **//** comment above an assignment and a **/* ... */** comment explaining a longer decision.
3. Remove the semicolon after **$first = "One"** in the short snippet and run **php -l** on a saved copy; restore the semicolon after observing the parse error.
4. Add a second HTML paragraph outside the PHP block and refresh the browser page.
5. Add an HTML comment around a harmless static note and observe that it does not appear in the rendered page.
6. Explain why an HTML comment is not a PHP comment.
7. Rewrite a comment that repeats the next statement so it provides useful context instead.

## Key takeaways

- Simple PHP statements are separated with semicolons; a newline is not enough.
- A closing **?>** can terminate the final statement in a block, but keeping the semicolon is clearer.
- Use **//** for a line comment and **/* ... */** for a block comment.
- PHP block comments do not nest.
- HTML comments affect markup display but do not disable server-side PHP execution.
- Comments should clarify intent and are not included as PHP output.
