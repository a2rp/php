# 056 - Serialization and Safe Data Exchange: Example

## Question

How can a PHP class explicitly choose which state to serialize, and how should the same information be exchanged with another system?

## Complete example

This PHP 8.0+ example demonstrates a controlled local PHP object round-trip, then uses a versioned JSON envelope for data exchange. The serialized bytes are generated by this program only. Never replace them with request, cookie, upload, or otherwise untrusted data.

~~~php
<?php

declare(strict_types=1);

final class ReadingList
{
    private string $owner;
    private array $titles;

    // Represents state that belongs only to the current runtime.
    private ?string $runtimeState = null;

    public function __construct(string $owner, array $titles)
    {
        $this->owner = $owner;
        $this->titles = self::validateTitles($titles);
        $this->runtimeState = 'initialized in this process';
    }

    public function __serialize(): array
    {
        // Persist only the fields that are part of the stable data contract.
        return [
            'owner' => $this->owner,
            'titles' => $this->titles,
        ];
    }

    public function __unserialize(array $data): void
    {
        if (!isset($data['owner']) || !is_string($data['owner'])) {
            throw new UnexpectedValueException('The owner must be a string.');
        }

        if (!isset($data['titles']) || !is_array($data['titles'])) {
            throw new UnexpectedValueException('The titles must be an array.');
        }

        $this->owner = $data['owner'];
        $this->titles = self::validateTitles($data['titles']);

        // Do not try to restore process-specific resources or state.
        $this->runtimeState = null;
    }

    public function owner(): string
    {
        return $this->owner;
    }

    public function titles(): array
    {
        return $this->titles;
    }

    public function runtimeStateWasReset(): bool
    {
        return $this->runtimeState === null;
    }

    public function toArray(): array
    {
        return [
            'owner' => $this->owner,
            'titles' => $this->titles,
        ];
    }

    private static function validateTitles(array $titles): array
    {
        foreach ($titles as $title) {
            if (!is_string($title)) {
                throw new UnexpectedValueException(
                    'Every title must be a string.'
                );
            }
        }

        return $titles;
    }
}

$list = new ReadingList(
    'Asha',
    ['PHP basics', 'Safe data exchange']
);

// This value was just created by this controlled example.
// Do not use unserialize() on untrusted or user-controlled bytes.
$serialized = serialize($list);
$restored = unserialize($serialized, [
    'allowed_classes' => [ReadingList::class],
    'max_depth' => 32,
]);

if (!$restored instanceof ReadingList) {
    throw new RuntimeException('The expected ReadingList was not restored.');
}

echo "PHP object round-trip:\n";
echo 'Owner: ' . $restored->owner() . "\n";
echo 'Titles: ' . implode(', ', $restored->titles()) . "\n";
echo 'Runtime state reset after restore: '
    . ($restored->runtimeStateWasReset() ? 'yes' : 'no')
    . "\n\n";

// A JSON envelope is a clearer contract for APIs and other systems.
$payload = [
    'version' => 1,
    'type' => 'reading-list',
    'data' => $list->toArray(),
];

$json = json_encode(
    $payload,
    JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR
);

echo "JSON for exchange:\n";
echo $json . "\n\n";

// A MAC can detect changes when the key is kept secret.
// This literal is only a demo key; use a protected secret store in an app.
$demoKey = 'demo-only-replace-with-a-protected-secret';
$signature = hash_hmac('sha256', $json, $demoKey);

// The receiver authenticates the exact bytes before decoding them.
$receivedJson = $json;
$receivedSignature = $signature;
$expectedSignature = hash_hmac('sha256', $receivedJson, $demoKey);

if (!hash_equals($expectedSignature, $receivedSignature)) {
    throw new RuntimeException('The JSON payload failed authentication.');
}

$decoded = json_decode(
    $receivedJson,
    true,
    32,
    JSON_THROW_ON_ERROR
);

// Valid JSON still needs application-level schema checks.
if (!is_array($decoded)
    || ($decoded['version'] ?? null) !== 1
    || ($decoded['type'] ?? null) !== 'reading-list'
    || !isset($decoded['data'])
    || !is_array($decoded['data'])
    || !isset($decoded['data']['owner'])
    || !is_string($decoded['data']['owner'])
    || !isset($decoded['data']['titles'])
    || !is_array($decoded['data']['titles'])) {
    throw new RuntimeException('The JSON payload has an unexpected shape.');
}

foreach ($decoded['data']['titles'] as $title) {
    if (!is_string($title)) {
        throw new RuntimeException('Every title must be a string.');
    }
}

echo 'Verified JSON owner: ' . $decoded['data']['owner'] . "\n";

// Altering a byte changes the expected MAC. Reject it before decoding.
$tamperedJson = str_replace('Asha', 'Mira', $receivedJson);
$tamperedExpectedSignature = hash_hmac(
    'sha256',
    $tamperedJson,
    $demoKey
);
$tamperedAccepted = hash_equals(
    $tamperedExpectedSignature,
    $receivedSignature
);

echo 'Tampered payload accepted: '
    . ($tamperedAccepted ? 'yes' : 'no')
    . "\n";
~~~

## How it works

- The ReadingList class implements __serialize() and __unserialize(). The serialization hook returns only the stable owner and title data.
- __unserialize() checks the restored owner and title values before assigning them. It resets process-specific state rather than trying to persist it.
- The example calls unserialize() only on bytes it has just generated itself. Its allowed_classes list and depth limit are extra constraints for that controlled demonstration; they do not make untrusted serialized input safe.
- The JSON envelope includes a version and a type so the receiver can check the data contract explicitly.
- JSON_THROW_ON_ERROR makes invalid JSON an exception. The following checks validate the envelope and each title; valid JSON alone is not proof of valid application data.
- The HMAC is calculated over the exact JSON string and verified before decoding. The demo key is hard-coded only to keep the example self-contained. Real applications must load a strong secret from protected configuration.
- Changing Asha to Mira changes the payload bytes, so the original HMAC no longer matches. HMAC detects modification but does not encrypt or conceal the JSON.

## Try it yourself

1. Add a numeric title and confirm that validation rejects the restored data.
2. Add a private field to ReadingList but leave it out of __serialize(). Confirm it is not included in the serialized state.
3. Change the envelope version to 2 and update the receiver to reject unsupported versions.
4. Change one character in $receivedJson without changing $receivedSignature. Confirm verification fails before JSON decoding.
5. Replace the demonstration key with a value loaded from an environment variable or secret manager. Do not commit a real secret.
6. Remove the HMAC section and observe that JSON parsing and schema validation still work, but no longer detect tampering.

## Common mistakes

- Copying serialized values from a request, cookie, or upload into unserialize().
- Assuming allowed_classes or max_depth makes attacker-controlled serialized data safe.
- Persisting connections or other runtime-only objects as if they were durable data.
- Including passwords, tokens, or internal fields in __serialize() without a specific design.
- Treating JSON syntax as sufficient validation for application input.
- Comparing signatures with a regular string comparison instead of hash_equals().
- Forgetting that HMAC is not encryption.
- Committing a real HMAC key in source control.

## Key takeaways

- Use PHP serialization only for controlled, PHP-specific state where its class coupling is understood.
- Never pass untrusted data to unserialize().
- Use modern serialization hooks to choose and validate object state.
- Use versioned JSON and validate its decoded shape for data exchange.
- Verify an HMAC before interpreting a signed payload; keep its key protected.
- HMAC detects modification but does not provide confidentiality.
